# Evidence and Experiments

Use this reference when the decision requires new evidence, evidence conflicts, or a test must separate learning from delivery.

## Claim–evidence fit

| Claim | Strong starting evidence | Common limit |
| --- | --- | --- |
| What people mean, fear, value, or find constrained | Focused interview, debrief, support conversation, artefact review | Does not prove future repeated behaviour. |
| What people do in a defined workflow | Direct observation, task trace, existing product behaviour | May be selected, confounded, or context-specific. |
| Whether a solution is understandable | Usable prototype, walkthrough, task observation | Does not prove reliable operational performance. |
| Whether an operational system works | Narrow code pilot, representative cases, realistic workflow checks | Does not establish broad demand by itself. |
| Whether an initiative is feasible/safe/allowed | Domain expertise, technical investigation, policy/security review | Does not prove user value. |

Evidence is not a universal hierarchy. Judge it by proximity to the claim, bias, context, decision relevance, and the consequence of being wrong.

## Test design

State these before running a substantive test:

1. **Hypothesis:** what must be true for the decision to stand?
2. **Actor and context:** whose behaviour or judgment matters, under what conditions?
3. **Signal:** what observation, decision, or artefact would be informative?
4. **Interpretation rule:** what supports, weakens, invalidates, or leaves the result inconclusive?
5. **Time window and constraints:** when and where is the test valid?
6. **Next decision:** what will change after each possible result?

If the test cannot plausibly alter a decision, do not run it as research. If the test is too poor to distinguish the intended question from interface confusion, unreliable delivery, or sample mismatch, improve the test or state the limit.

## Measurement restraint

Choose an outcome before selecting a metric. For each proposed signal, ask:

- What decision will this inform?
- Does it measure a meaningful change or only an easy proxy?
- What privacy, implementation, interpretation, or incentive cost does it add?
- Is a lighter observation sufficient for the current scale and frequency?

Do not claim causation from a correlation without a credible comparison. Do not optimise a target without considering how it can be gamed or what it leaves out.
