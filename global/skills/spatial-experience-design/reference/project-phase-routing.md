# Spatial Project Phase Routing

Use this reference when a Spatial request names an old workflow phase, resumes a substantial interior/spatial website project, or needs a clear boundary between a direct specialist task and project coordination.

## The one coordination route

Use `spatial-project-inception` when a major new or substantially redesigned
spatial website needs linked creative decisions, evidence, production planning,
or a resumable handoff. Preserve four working questions in the smallest useful
record: what is known, what has been chosen, how the experience should behave,
and what must be made and proven. Existing approved work may answer them.
Do not create a fixed file set to begin useful exploration.

## Focused phase routing

| Named need | Load directly | Preserve from the former route | Escalate to the project route when |
| --- | --- | --- | --- |
| Analyse references or decide what to borrow | `reference-intelligence` | source provenance; observed versus inferred evidence; Keep/Adapt/Reject/Defer; removability and pattern-concentration checks | the result changes the brief, selected concept, or more than one downstream contract |
| Explore whole-page concept directions | `spatial-experience-design`, plus `reference-intelligence` if references are involved | enough structural divergence to reveal the real choice; a restrained/still-led alternative when useful; a visible test for a consequential uncertainty | missing evidence or criteria could materially reverse the choice |
| Compare and select a territory | `spatial-experience-design`, `storytelling`, and `master-design-director` | compare full-page logic, proof, assets, stillness/motion, accessibility, performance, maintenance, and inquiry; retain rejected-option rationale and reversal condition | selection needs user approval, alters linked contracts, or creates a hybrid needing recorded tradeoffs |
| Define story, chapters, proof, and inquiry | `storytelling`, with `spatial-experience-design` | controlling argument; at least two compatible narrative forms; chapter jobs; copy/visual/stillness responsibilities | the task must also reconcile concept, production, or user approval |
| Turn an approved blueprint into spatial UI or a vertical slice | `ui-ux`, `spatial-experience-design`, `coding`, and `master-design-director` | static composition before motion; risk prototype first; desktop/mobile/accessibility/proof/inquiry checks | the project needs a coordinated production contract or a decision may invalidate the selected concept |
| Build approved spatial production slices | `build-feature`, with `spatial-experience-design`, `ui-ux`, and only needed specialist references | coherent visitor-responsibility slices; real-enough assets; per-slice concept-continuity audit; evidence before final approval | scope, asset, dependency, or concept assumptions change materially |
| Add approved non-trivial motion | `cinematic-motion`; add `motion-library` only for a named motion job | stillness comparison; separate track ownership; riskiest-mechanic prototype; mobile/reduced-motion/performance fallbacks | motion requires a new project contract, media cost/rights approval, or changes the experience architecture |
| Coordinate media sources and web states | `media-choreography`; add `scroll-storyboard` only when scroll authors meaning or media state | brand-to-scene translation; proof and text-safe choreography; asset and fallback map | scene decisions change the selected concept, proof strategy, or asset/rights boundary |
| Evaluate one contained realtime effect | `canvas-ui`, with `cinematic-motion` owning narrative motion when present | still/DOM/media comparison; semantic fallback; upstream source and licence check; isolated vertical slice | the effect changes architecture, adds a dependency, or cannot preserve the approved experience without Canvas/WebGL |
| Generate an approved website film | Media profile plus `video-generation`; add `prompt-engineering` only for the provider-ready prompt | inherited scene brief; continuity and rights checks; provider facts; generation approval boundary | the clip changes the experience architecture, requires new client evidence, or triggers upload, credit, or external-account effects |

## Direct-work safeguards

- Direct work is not lesser work. It simply does not create workflow state by default.
- Do not infer that a named phase authorises production, dependency changes, external research, uploading references, credit spend, publishing, or delivery.
- Keep reference evidence, creative decisions, prototype results, and unverified claims in the active project context only when a user-authorised project actually needs them.
- A focused task may stop with a recommendation, a rough test, or a decision record. It never has to force all three V5 working loops.
- A failing later task returns to the earliest invalidated assumption: evidence, brief, territory, experience architecture, production contract, prototype, or implementation slice.

## Discovery language

Treat these requests as direct specialist work unless the escalation criteria above apply:

- “Analyse these design references.”
- “Give me three spatial website directions.”
- “Help choose between these concepts.”
- “Develop the website story.”
- “Design this approved section.”
- “Make this approved motion work.”

Treat this as `spatial-project-inception`:

- “Start or rescue this complete interior/spatial brand website from research to a build-ready plan.”
- “Coordinate the evidence, concept, story, production plan, and approval gates for this showroom project.”

## Visible handoff

At each material handoff, state the current route and lens, decision being
protected, capabilities selected/loaded/used, evidence or artifact produced,
unresolved question or approval, next route and reason, and the condition that
would return the work to an earlier decision. Keep the report compact. Do not
make the user name the next skill or interpret a capability inventory.

Treat `design-director` as the functional owner. Treat
`master-design-director` as its conditional critique and gate method, not a
second agent or parallel owner.

## Verification before a handoff

- The selected route matches the real decision scope.
- The chosen specialist skills are explicit and their conditional references are not loaded wholesale.
- Any concept or story decision traces to approved evidence and the creative brief.
- Motion, media, dependencies, and external effects stop at their separate approval gates.
- The result states the next smallest useful action and any return condition.
