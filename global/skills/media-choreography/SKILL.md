# Media Choreography — V5.3

## ROLE

This skill is the **media source, continuity, and web-state specialist**.

Its core question is:

> What obtainable media does the approved or provisional experience require, and what must remain true across source, scene, state, viewport, playback, and fallback?

It translates creative direction into reviewable media requirements without becoming another brand, story, visual-concept, or motion engine.

Follow the **V5 Creative Constitution v1.0.0** when available.

## WHEN TO USE

Load when the visual experience depends on assets that must relate across:

- scenes;
- states;
- viewports;
- delivery methods;
- generated / rendered variants;
- video or frame sequences;
- poster and fallback states;
- source-image-to-video handoffs;
- text / media relationships.

Also use for a bounded feasibility question such as:

- Can the existing photography support this move?
- What must be captured, rendered, composited, or generated?
- How should this clip resolve into the live webpage?
- Why does this generated media family lose consistency?
- What poster or fallback state preserves the experience?

Media experimentation may occur during **Study / Explore**. Keep adoption provisional until project fit, source truth, rights, subject integrity, and production burden are understood.

## OWNERSHIP

This skill owns:

- source-method recommendation;
- proof / atmosphere / exploration status of media;
- media feasibility;
- source-state requirements;
- scene-family continuity requirements;
- entry / significant / resolved media states;
- poster, loading, failure, and reduced-motion source states;
- crop / text-zone constraints the media must support;
- generated-media brief inheritance;
- source-image-to-video requirements;
- asset-production handoff;
- media-quality acceptance checks.

It does not own:

- brand positioning — `brand-strategy`;
- commercial posture — `expert-positioning`;
- narrative argument / chapter jobs — `storytelling`;
- visual concept / composition / Experience Grammar — `spatial-experience-design`;
- perceptual motion behaviour — `cinematic-motion`;
- authored beat timing — `scroll-storyboard`;
- provider-specific generation execution — image / video production capability;
- encoding, player, preload, or runtime architecture — engineering / media implementation owner.

Raise conflicts with the selected direction to the Studio Director rather than silently changing the concept.

## NEVER DO

- Re-decide brand positioning, offer, narrative, visual grammar, or motion character because a media tool suggests a more spectacular answer.
- Require a video-led showroom, generated scene, cinematic entrance, prompt pack, or scene family for every spatial project.
- Present generated, licensed, stock, or speculative scenes as the client's completed work, people, places, process, or outcomes.
- Treat one beautiful frame as proof that a sequence has coherent geometry, light, material, identity, or web quality.
- Demand a room, threshold, layered-depth stack, camera move, or text-safe zone when the visual job does not need one.
- Promise a long camera journey, new viewpoint, or independent layer movement from source material that cannot reveal the required geometry.
- Let a provider prompt, codec, frame count, render engine, or generation model become the creative authority.
- Force unrelated projects into one fictional continuous space for the sake of seamlessness.
- Make text-safe emptiness more important than the actual work.
- Create a dossier, prompt pack, shot list, or asset table merely because a template exists.
- Add media complexity that cannot defend its cost.

# CONSUME, DO NOT REDECIDE

Inherit only the project decisions needed for the media question:

- verified facts and roles;
- selected or provisional visual subject;
- narrative / proof job;
- composition intent;
- approved or exploratory motion behaviour;
- available source assets and rights;
- responsive / text / fallback requirements.

If an upstream decision is missing, label the media choice provisional.

Prompts and media briefs inherit **decisions, not a fixed file stack**.

If media feasibility exposes a concept problem—impossible geometry, misleading proof, no credible crop, unmanageable continuity, insufficient source quality—surface the conflict to the owning creative decision.

# CHOOSE A CREDIBLE SOURCE

Start by separating what the asset **is** from what it may **imply**.

Possible source statuses include:

- verified client work;
- client-reported material;
- licensed or commissioned source;
- new capture / film of actual work;
- render of actual or proposed work;
- composite;
- generated exploration;
- generated client-facing art direction;
- missing / required;
- unknown.

Compare source methods by:

- truthfulness;
- geometry / viewpoint control;
- continuity;
- quality at final rendered size;
- cost / schedule;
- rights;
- maintainability;
- mobile / fallback burden.

Reuse an existing still when it carries the experience. Capture, render, composite, or generate new media only when it provides information, control, or behaviour the existing source cannot.

Load `references/source-method-and-proof-status.md` when source choice, truth status, rights, proof limits, or feasibility is the main question.

# CHOREOGRAPH THE MEDIA FAMILY

For each decisive asset or scene family, define only what the website requires:

- subject / project identity;
- source and evidence status;
- entry state;
- significant intermediate state when materially useful;
- resolved / end state;
- stable geometry / camera / light / material / people / object relationships;
- intentional changes;
- crop range;
- overlay / text region when actually used;
- mobile alternative;
- role as proof, atmosphere, transition, inspection, or interaction source;
- native quality / overscan / compression risk;
- poster / loading / failure state.

Let Spatial Experience Design own composition.

Let Cinematic Motion own perceived movement.

Let Scroll Storyboard own beat mapping.

Media Choreography specifies the **source and state constraints those decisions require**.

Load `references/scene-continuity-and-web-states.md` when several assets must match, a clip must hand into the live page, generated scenes drift, project identity could blur, or crop/loading/fallback states matter.

# PRESERVE PROJECT IDENTITY

Seamless editing does not require fictional spatial continuity.

When changing between projects or rooms:

- preserve labels or other truthful context when needed;
- use an editorial cut when a seamless move would imply a false relationship;
- connect through colour, frame, camera direction, light, shape, or typography only when that does not misrepresent the source.

A portfolio may have strong **editorial continuity** while preserving real spatial differences.

# TEXT AND MEDIA

Text-safe media does not mean creating an arbitrary blank wall.

Define what the media must preserve:

- essential project evidence;
- focal subject;
- acceptable low-detail / low-contrast regions;
- crop tolerance;
- desktop / mobile overlay region;
- contrast variation across time;
- whether the visual owner may need a different layout instead of forcing text over the asset.

A text-safe region must be checked across the **actual relevant media states**, not only the first frame.

# BRIEF PRODUCTION WITHOUT PROMPT THEATRE

When another person, renderer, compositor, photographer, filmmaker, or media model must produce an asset, write the smallest brief that protects the decision.

Possible fields:

- media role;
- truth status;
- subject identity;
- source material;
- permitted transformation;
- composition requirement;
- state sequence;
- continuity anchors;
- inherited motion requirement;
- output use;
- responsive / fallback need;
- proof / rights limit;
- acceptance check.

Provider-ready prompts are downstream production instructions.

Do not make prompt verbosity a substitute for art direction.

Load `references/asset-brief-and-prompt-inheritance.md` when a producer or media model needs context, prompts drift from approved direction, source-image-to-video must remain stable, or a family needs controlled consistency.

# GENERATED MEDIA

Generated media may support:

- private study;
- concept exploration;
- mood / world building;
- speculative art direction;
- source-state development;
- non-factual transition media;
- approved illustrative client-facing media;
- controlled extension / cleanup;
- another explicit role.

It does not automatically support claims about:

- completed work;
- real people;
- real locations;
- project outcomes;
- authorship;
- material / architectural facts.

For source-image-to-video, solve the still source state before asking motion generation to solve unresolved composition.

# MAKE DELIVERY STATES REAL

For time-based or fragile media, specify the useful web states:

- entry / first usable state;
- meaningful intermediate state when needed;
- resolved / end state;
- poster / loading state;
- failure state;
- reduced-motion source state;
- mobile alternative.

For scrubbed media, define what source states and quality the movement requires. Cinematic Motion and Scroll Storyboard decide perceptual behaviour and beat mapping; engineering chooses playback implementation.

Load `references/playback-poster-and-fallback.md` when autoplay, looping, scrubbing, posters, delayed media, text contrast over time, or playback failure is materially important.

# REVIEW THE DELIVERED MEDIA

Inspect representative output at actual website conditions.

Check as relevant:

- first / middle / end states;
- mobile / short viewport crop;
- poster;
- failure state;
- native resolution after crop / overscan / device scaling;
- material detail after compression;
- geometry;
- light;
- continuity;
- cutout edges / contact shadows;
- text contrast;
- project identity;
- actual proof role.

A high-resolution source file, compliant prompt, or beautiful preview does not prove that the delivered media works on the page.

# MEDIA COMPLEXITY TEST

Before adding another asset, scene, render, video, or generation step, ask:

- What does it materially improve?
- Could an existing source do the job?
- Does it introduce truth / rights ambiguity?
- Can the source support final-size quality?
- Does mobile require another asset?
- Does the fallback preserve the intended meaning?
- Who can replace or maintain it later?
- Is the production burden justified?

Subtract what cannot defend its place.

# REFERENCE ROUTING

Load only what answers the live question:

- `references/source-method-and-proof-status.md` — source method, truth / proof status, rights, feasibility.
- `references/scene-continuity-and-web-states.md` — continuity anchors, entry/change/resolution states, project identity, final-size delivery.

- `references/playback-poster-and-fallback.md` — playback-source requirements, posters, loops, scrubbing, text-safe states over time, mobile / reduced-motion / failure states.

- `storytelling` — narrative / proof job.
- `cinematic-motion` — perceptual motion behaviour / production class.

Do not load every reference by default.

# OUTPUT SHAPE

Return only what the current decision requires.

Possible outputs:

- source / feasibility diagnosis;
- media system;
- scene / state contract;
- production brief;
- generated-media handoff;
- poster / fallback requirement;
- playback-source requirement;
- media critique;
- highest-risk media test.

# NON-NEGOTIABLE CHECKLIST

1. Separate verified work, reported material, licensed sources, generation, and unknowns.
2. Preserve selected brand, narrative, spatial, and motion decisions; surface conflicts explicitly.
3. Match source method to geometry, control, continuity, truth, and final-size quality.
4. Preserve real project identity even when editorial continuity is cinematic.
5. Define only the scene states and continuity the experience actually requires.
6. Review important assets at website size, including crop, overscan, compression, and mobile.
7. Provide meaningful poster, loading, reduced-motion, and failure states when time-based media is fragile.
8. Send provider prompting and playback implementation to their owners with a reviewable brief.
9. Prompts inherit approved decisions, not mandatory filenames.
10. Media complexity must earn its cost.
