# Conditional CRO Experiment Candidates

Load only after a decision brief, evidence register, and falsifiable hypothesis exist. Every row is a candidate question, not a promised tactic or universal best practice.

## Use This Table

For each candidate, state the mechanism, eligible audience, primary outcome, guardrails, risk, and what result would reject the hypothesis. Keep required accessibility, privacy, safety, and defect fixes out of randomised variants.

## Message and Comprehension

| Candidate | Question to answer |
| --- | --- |
| Headline or subheadline variant | Does a clearer proposition improve the intended task for the actual acquisition context without increasing misleading interpretation? |
| Message-match variant | Does matching the landing message to the source promise reduce early task failure without narrowing useful context? |
| Benefit versus feature framing | Does the chosen framing improve comprehension or qualified progression for the affected audience? |
| Section order | Does moving decision-critical information earlier help users complete the task without hiding material limits? |
| Content depth or format | Does a shorter, longer, visual, or interactive explanation answer the user's question better for this context? |

## Action and Navigation

| Candidate | Question to answer |
| --- | --- |
| CTA wording | Does the label make the intended action and consequence clearer than the current label? |
| CTA hierarchy | Does the proposed priority help users choose the intended action without removing a legitimate secondary task or escape route? |
| CTA visibility or placement | Is visibility the observed failure, and does the change improve findability at the point users are ready to act? |
| Navigation or comparison link | Does preserving or changing navigation help users complete the decision without creating a dead end? |
| Progressive disclosure | Does staged detail reduce overload while keeping material information available before commitment? |

## Forms, Signup, and Checkout

| Candidate | Question to answer |
| --- | --- |
| Field purpose or timing | Does changing a field's timing or explanation reduce burden while preserving valid data, privacy, qualification, and accessibility? |
| Form sequence | Does the sequence help users complete the task without increasing errors or abandonment at later steps? |
| Error assistance | Does clearer identification and recovery improve valid completion without hiding the user's input or state? |
| Progress and expectation | Does showing the real number of steps improve completion without creating pressure or a false promise? |
| Checkout or pricing explanation | Does clearer scope, cost, or plan information reduce uncertainty without hiding fees or conditions? |

## Proof and Trust

| Candidate | Question to answer |
| --- | --- |
| Relevant proof placement | Does authenticated, current, permitted proof answer a documented trust question at the point it arises? |
| Case-study or testimonial format | Does the evidence format improve understanding without implying typical or guaranteed results? |
| Security or compliance explanation | Does a precise, current explanation reduce a known concern without using an outdated or decorative badge? |
| FAQ or objection content | Does answering a documented question improve the user's decision without adding unsupported claims? |

## Performance and Access

| Candidate | Question to answer |
| --- | --- |
| Page-load or media treatment | Does the change reduce user harm or delay for the affected device/network context without reducing comprehension or access? |
| Responsive layout | Does the layout support the task across the real device population and input modes? |
| Accessible interaction path | Does the corrected path meet the relevant requirement and user task? Use conformance verification, not a conversion experiment, when it is a required fix. |

## Method and Integrity Notes

- Prefer a qualitative or accessibility study when the question is why users fail, whether they understand, or whether an interaction is accessible.
- Prefer an instrumentation audit when exposure or event validity is uncertain.
- Use a controlled experiment only when assignment, exposure, outcome, traffic, duration, and guardrails can support the decision.
- Preserve the control and treatment, randomisation unit, primary outcome, guardrails, stopping logic, and analysis plan before launch.
- Record version, audience, device/network scope, implementation changes, and external factors. Treat a post-hoc segment as exploratory unless it was planned and adequately supported.
- Do not test false urgency, hidden fees, obstructed cancellation, weakened consent, inaccessible interaction, or another harmful pattern to see whether it converts.
