# Design-Audit Reference Library

## What This Is

This directory contains 30 local reports on noteworthy digital experiences.
They are a **candidate precedent library** for qualifying Spatial work: interior
and architectural portfolios, showroom sites, gallery-like experiences, and
other projects where a reference question can materially improve the direction.

It is not a design template, an implementation library, or a requirement to
use cinematic motion. A report may help an agent decide to keep a page still,
use simpler DOM-led composition, or reject a pattern that does not fit the
brand, assets, audience, or delivery constraints.

## When an Agent Uses It

1. Establish the current brand/project evidence and a named design question.
2. Use `reference-intelligence` to inspect supplied recordings, screenshots,
   transcripts, or this local corpus.
3. Use the [Spatial adaptation map](../skills/spatial-experience-design/reference/audit-mechanics-map.md)
   only when the project qualifies for the Spatial pack.
4. Read the smallest relevant raw report, then make a `KEEP`, `ADAPT`,
   `REJECT`, or `DEFER` decision. Do not copy layouts, timing, code, or identity
   literally.

For a new website recording, a vision-capable agent can inspect the recording
directly and record timecodes. If another AI turns that recording into a text
transcript, treat the transcript as a useful but **mediated** source: preserve
the recording/screenshots and do not treat guessed implementation details as
facts.

## Source Status

The reports record design observations and historical gap hypotheses. They do
not prove that a technique is current, accessible, mobile-safe, or right for a
new client. In particular, an individual report's "Upgrade Specifications" are
candidate ideas, not instructions to alter a skill or use a dependency.

## Guardrails

- Do not use a reference site's prestige as the reason to choose a pattern.
- Do not infer libraries, frameworks, or exact code from screenshots or a
  recording alone.
- Do not approve WebGL, canvas, image sequences, generated media, or a new
  dependency without its own asset, performance, accessibility, and approval
  check.
- Do not let a cinematic treatment hide absent proof, poor navigation, or a
  weak enquiry path.
