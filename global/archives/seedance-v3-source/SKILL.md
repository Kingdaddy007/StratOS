# Seedance

## WHEN TO USE THIS

- The provider is Seedance, ByteDance, Dreamina, Jimeng, Doubao, CapCut, or ModelArk.
- The task depends on a Seedance model label, multimodal reference inputs, audio-video generation, editing/extension, or an observed Seedance failure.
- The user needs a current, surface-scoped route before creating a prompt or production plan.

## NEVER DO

- Never treat Seedance 2.0, 2.5, Lite, Mini, Fast, or Pro as interchangeable names or infer capability, price, quality, access, or limits from a suffix.
- Never present a creator-UI control, API role token, release-announcement limit, community recipe, or historical workaround as a universal Seedance rule.
- Never advise filter bypass, identity/likeness concealment, provenance removal, or rights evasion.
- Never submit a generation, upload assets, call an API, spend credits, or publish without just-in-time approval.

## RESOLVE THE ACTIVE ROUTE

1. Record the creator/API surface, exact visible model label or API identifier, checked date, account access, country/region, plan or credits/API activation, task mode, and visible input/output controls.
2. Classify the job: `concept_test`, `reference_led_film`, `edit_extend`, or `troubleshoot`.
3. Build a production brief: subject, action, setting, temporal beats, camera, light, audio intent, continuity anchors, duration, aspect ratio, delivery target, and success criteria.
4. Build a rights and confidentiality inventory for every supplied face, voice, image, video, music, logo, artwork, brand, and client asset.
5. Use the active UI/API and dated source together. If they conflict or the surface is unknown, mark the control unverified and do not depend on it.
6. Preserve the prompt, settings, inputs, output, error, billing state, and a single-variable hypothesis when diagnosing a failed result.

## CURRENT SUPPORT MATERIAL

Use the parent capability as the active entry point while the inherited specialist set is reviewed one by one for preservation and surface scoping. It is unsafe to make the old 2.0-specific prompt, camera, audio, or reference material the default route until that review is complete.

## REFERENCE LOADING RULES

Start with [resource-index.md](references/resource-index.md).

- Load [surface-and-model-map.md](references/surface-and-model-map.md) before relying on a model/version fact, reference count, duration, editing/extension behavior, or API role.
- Load [platform-constraints.md](references/platform-constraints.md) only when a task specifically depends on the dated Seedance 2.0 launch claim.
- Load creative-method references only for their stated job. Do not use their old tags, fixed limits, or “best practice” wording as active platform facts.
- Route an observed policy refusal to `seedance-filter`, a rights/likeness question to `seedance-copyright`, and an implementation/integration decision to `seedance-pipeline`. Verify every provider-specific claim inside a specialist against the active surface.

## OUTPUT SHAPE

Return:

1. Surface/model/access record and unresolved facts.
2. Job-specific production brief and smallest verified route.
3. Surface-specific prompt or API guidance only where current evidence supports it.
4. Rights, confidentiality, provenance, budget, and approval gates.
5. Evidence record and an experiment plan that changes one variable at a time.

## NON-NEGOTIABLE CHECKLIST

1. Separate model family, version, surface, exact identifier, and current entitlement.
2. Scope every volatile fact with source and checked date.
3. Treat continuity, audio quality, motion, and edit fidelity as review criteria, not guarantees.
4. Preserve useful creative method without promoting stale syntax or limits.
5. Stop before external, paid, or publication effects.
