# V4 Spatial Capability Decision Ledger

**Status:** first preservation-and-relevance audit complete. This is not a
blanket rewrite approval.  
**Date:** 2026-08-19
**Scope:** the nine active Spatial skills, the one Spatial coordination route,
and the local Design-Audit reference library.

## Governing Question

For each Spatial asset, the question is not whether a capable model has heard
of design, motion, or storytelling. It is whether the asset provides reusable
specialist judgement, a selectively loaded library, or a decision/verification
gate that prevents a predictable failure when building a high-quality spatial
website.

The audit therefore preserves the method first, then identifies the few places
where fresh evidence is required before a substantive rewrite. File length,
skill count, and visual spectacle are not decision criteria.

## Current Shape

```text
Full interior/spatial website with linked decisions
  -> spatial-project-inception (the one coordination workflow)

Focused reference, story, concept, motion, or build question
  -> direct specialist skill(s), no task-state ritual

Named visual precedent question
  -> reference-intelligence
  -> local Design-Audit library only when useful
  -> Keep / Adapt / Reject / Defer decision
```

This preserves a rigorous full-project path without forcing somebody who asks
“help me plan motion for this gallery” through ten project phases.

## The Design-Audit Library Decision

The 30 reports are not 30 skills or hidden commands. They are a local precedent
library. Their correct use is selective:

1. Start with the client/project evidence and one named reference question.
2. Inspect a supplied recording or screenshots directly where possible.
3. If an AI transcript exists, retain it as `REPORTED`, rather than treating its
   technical guesses as a fact.
4. Retrieve only the relevant local report(s) through the library index and
   Spatial adaptation map.
5. Translate the useful principle to the current brand and record what is not
   being copied.
6. Decide `KEEP`, `ADAPT`, `REJECT`, or `DEFER` before a storyboard, prototype,
   or implementation changes.

The integration repair completed every report's discoverability: all 30 are in
the [library index](../global/design-audit/library-index.md), and all 30 have
a Spatial adaptation decision in the
[audit mechanics map](../global/skills/spatial-experience-design/reference/audit-mechanics-map.md).

## What Is Explicitly Not Happening

- No Spatial source was removed, compressed, or converted into a generic
  checklist in this audit.
- No design-audit “Gap” or “Upgrade Specification” is being treated as an
  instruction to add WebGL, GSAP, a dependency, or a new workflow.
- No video provider, model, API, screen recorder, or external analysis service
  is assumed. Those belong to the separate provider-aware Media package.
- No routine page, section, story, or motion request becomes a workflow merely
  because a more elaborate project could need one.
