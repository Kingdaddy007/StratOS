# V4 Scroll Craft Decision Ledger

**Decision owner:** Beloved, advised by the Studio Director and Design Director.
**Scope:** Evaluate the non-provider capabilities in `nateherkai/scroll-craft`
against the canonical V4 spatial website system.

## Evidence boundary

- The Scroll Craft repository and its skill references were inspected directly.
- The supplied comparative report is a non-independent synthesis of two model
  analyses. Agreement increases confidence in shared interpretation but is not
  separate implementation evidence.
- V4 source and routing were inspected locally. Runtime effectiveness remains a
  project-level pilot question.

## Decisions

| Item | Decision | V4 destination | Guardrail / test |
| --- | --- | --- | --- |
| Page grammar, grammar-specific forbids, signature move | Adapt | `spatial-experience-design/reference/page-grammar-and-fingerprint.md` | Must follow brand evidence and visible territory tests; no fixed grammar catalogue |
| Workspace fingerprint registry | Adapt | `site-fingerprints.md` context template | Workspace-scoped, no client secrets; similarity count is a warning, not quality proof |
| Feeling curve, primary peak, ending resolution | Adapt | `storytelling` and `scroll-storyboard` | Emotional pacing remains subordinate to controlling argument, proof, inquiry, and accessibility |
| Cold-scroll feel check | Adapt | `scroll-storyboard` and scroll verification | Manual evidence after implementation; compare intended versus felt |
| Dead-scroll, frozen-media, composited-contrast, focus, mobile, reduced-motion checks | Adapt | `cinematic-motion/reference/scroll-verification.md` and spatial verification route | Use project-native browser evidence; sampling and automation remain bounded |
| GOP/keyframe-density guidance | Adapt | scroll verification and production plan | Measure target clips and browsers; reject copied universal GOP values |
| Scroll Craft runtime engine, CSS progress architecture, scripts, and plugin packaging | Defer | None | Pilot V4-native contracts first; reconsider only if the existing stack cannot satisfy a measured need |
| Provider/API asset-generation pipeline | Reject for this upgrade | None | Existing Media routes retain provider-aware planning and approval gates |
| Fixed typography, spacing, act counts, device quotas, or universal grammar menu | Reject | None | Preserve V4's evidence-led, brand-specific, conditional design model |
| New permanent agent or competing top-level Scroll Craft skill | Reject | None | Existing Design Director, spatial skills, and verification routes own the capability |

## Smallest pilot

Run one real interior-designer website through the existing Spatial Project
Inception route. Compare the selected territory against the workspace
fingerprint ledger, implement only its approved scroll behavior, then execute
the scroll-verification contract on desktop, mobile, and reduced motion. Keep
the additions only if they reduce structural repetition or catch a material
failure without forcing spectacle or workflow ceremony.
